# Configuration Reference

All configuration is done through environment variables in `.env`. The installer generates this file from `.env.example` and fills in secrets automatically.

## Required secrets

These are generated by `install.sh`. If you're setting up manually, generate them yourself:

| Variable | Purpose | Generate with |
|----------|---------|--------------|
| `AUTH_SECRET` | Signs session tokens | `openssl rand -base64 32` |
| `OPENSEO_ENCRYPTION_KEY` | AES-256-GCM key for encrypting stored API keys | `openssl rand -base64 32` |

Both must be base64-encoded 32-byte values. Don't reuse them.

## URLs

| Variable | Default | Notes |
|----------|---------|-------|
| `NEXT_PUBLIC_SITE_URL` | `http://localhost:4720` | Public URL users access. Change if behind a reverse proxy. |
| `FRONTEND_URL` | `http://localhost:4720` | Should match `NEXT_PUBLIC_SITE_URL`. |
| `PORT` | `4720` | Host port the app is exposed on. |

If you're behind a reverse proxy with TLS, set both URL variables to your `https://` domain.

## Database

| Variable | Default | Notes |
|----------|---------|-------|
| `DB_PASSWORD` | `openseo` | Password for the Postgres container. `install.sh` generates a random one. |
| `DATABASE_URL` | `postgresql://openseo:openseo@localhost:5432/openseo` | **For local dev only.** See important note below. |

## Storage

| Variable | Default | Notes |
|----------|---------|-------|
| `STORAGE_DRIVER` | `local` | `local` for filesystem, `s3` for S3-compatible storage. |
| `S3_ENDPOINT` | -- | e.g. `https://<account>.r2.cloudflarestorage.com` |
| `S3_BUCKET` | -- | Bucket name |
| `S3_REGION` | -- | e.g. `auto`, `us-east-1` |
| `S3_ACCESS_KEY_ID` | -- | |
| `S3_SECRET_ACCESS_KEY` | -- | |
| `STORAGE_PUBLIC_URL` | -- | Public CDN URL for serving uploaded files |

Default is local filesystem. Uploads go into the `uploads_data` Docker volume.

| Variable | Notes |
|----------|-------|
| `IDEOGRAM` | Enables AI image generation |
| `PEXELS` | Enables stock photo search |

Both are optional.

## CORS

| Variable | Notes |
|----------|-------|
| `ALLOWED_ORIGINS` | Comma-separated origins for cross-origin API calls. Empty = same-origin only. Example: `https://app.example.com,https://example.com` |
| `ALLOWED_DEV_ORIGINS` | Hostnames the Next.js dev server trusts for LAN testing. Example: `192.168.1.154,10.0.0.5` |

## Worker

| Variable | Default | Notes |
|----------|---------|-------|
| `DISABLE_INLINE_WORKER` | `0` | Set to `1` when running a dedicated worker container. See [Docker Compose docs](docker-compose.md) for details. |

## Important: compose.yml overrides DATABASE_URL and REDIS_URL

The `DATABASE_URL` and `REDIS_URL` values in `.env.example` are for **local development only** (running the app outside Docker). Inside Docker, `compose.yml` hardcodes these to the internal container hostnames (`postgres:5432`, `redis:6379`).

This means: if you want to use an external database or Redis, you can't just change `.env`. You need to edit `compose.override.yml` to remove or change the environment overrides in the `app` service. See [Docker Compose customization](docker-compose.md#customization).
